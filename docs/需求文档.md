# 首都机场（飞行区）电动车辆安全运行监控管理平台 — 需求文档

> 开发基线：本章对齐《第三章 项目需求》本次给定条款（总述、运行服务、平台功能第 1–5 项及功能总述）。第 3.3 节监控预警同时吸收应答文件「三）、平台服务具备主要功能」第 3 条的实现方案；原文未写明的交互、口径和字段以应答为准。
> 带「*」的条款及其全部下级条款为重要技术条款，负偏离将导致应答被否决。本次给定正文未标出具体「*」条款；后续原文补标后，按原文执行。

## 1. 项目概述

采购人采购首都机场电动汽车安全运营管理服务。供应商提供飞行区内电动车辆安全运行监控管理平台，把现存及新增电动车辆全部纳入监控。

| 项 | 要求 |
|----|------|
| 监控范围 | 首都机场飞行区现存及新增电动车辆，全部接入 |
| 当前规模 | 约 1900 余辆 |
| 2029 年规模 | 空侧约 2800 辆，其中通用车 1600 辆、特种车 1200 辆 |
| 硬件 | 平台运行及数据服务器由采购人提供 |
| 运维责任 | 应答人负责服务器及数据运维 |
| 容量设计 | 按 2800 辆、365×24 小时持续上报做接入、存储、查询与展示 |

## 3. 平台功能（原文「二」）

平台用大数据分析做碳减排与能源消耗等经济性、环境性指数，以及可靠性指数、安全性指数的分析与展示。数据监视同时提供 Web 与移动端。

车辆运行数据 24 小时实时监控，可查看最新数据与状态，并支持历史数据统计回放。

每周、月、半年、年出具新能源汽车运行监控报告，做定量分析，并给出生产运营建议。

谈判文件要求地图看车、监控统计、充电热力图、在线与实时上报、单车详情、历史轨迹回放、实时告警与报文导出、短信 / 微信推送。下列交互、口径和字段按应答文件第 3 条补全。

在线判定全站统一：最近 60 秒内有数据上报记为在线，超时记为离线。总览 F-02-05 使用同一口径。

#### 充电热力图（F-03-03）

使用率 = 该区域充电车辆在所选时段内的累计充电时长 ÷（桩数 × 时段总时长）。颜色越深，该区域充电桩越繁忙。本图表示充电桩使用程度，与总览的 24 小时车辆运行热力图分开。

| 使用率 | 颜色 |
|--------|------|
| 0%～20% | 浅绿 |
| 20%～40% | 中绿 |
| 40%～60% | 黄 |
| 60%～80% | 橙 |
| 80%～100% | 深红 |

| 项 | 要求 |

#### 告警级别、查询与导出（F-03-07）

告警级别可配置。级别为严重时视为重点车辆告警。高危报警专项报告（F-06-04）对应严重级别。

| 级别 | 含义 | 展示与触达 |
|------|------|------------|
| 严重 | 可能导致人身伤害或重大财产损失，如电池热失控前兆 | 红色、持续弹窗，并短信推送。车辆进入重点关注池，总览单独展示，故障解除后移出 |
| 重要 | 影响车辆正常使用，如绝缘故障 | 橙色，列表置顶 |
| 一般 | 轻微异常，如单个温度传感器失效 | 黄色 |

| 类型 | 字段 |
|------|------|
| 查询条件 | 设备识别码、车辆自编号、故障类型、故障码、故障原因，支持组合查询 |
| 列表字段 | 设备识别码、车辆自编号、车辆单位、故障类型、故障码、故障原因、告警方式（平台弹窗 / 短信 / 微信）、故障日期、故障发生时间、故障最后更新时间 |
| 其它能力 | 告警次数统计；查看该告警触发时刻的原始上行报文，十六进制与 ASCII 对照；勾选或全部导出为表格，导出记入审计日志 |

#### 消息推送（F-03-08）

| 通道 | 场景 |
|------|------|
| 短信 | 严重告警、满电提示。发送失败自动换通道重试 |
| 微信小程序订阅消息 | 各等级告警与日常通知，需用户授权 |
| 站内信 | 全部通知。登录可见，未读提醒 |

推送规则：

- 严重告警同时走短信、小程序、站内信。
- 满电提示在 SOC 达到 100% 或达到设定阈值时发出，通知车辆使用方，通道为短信或小程序。

## 5. 验收标准

1. F-01 至 F-06 的页面可访问、有数据、可交互。
2. 登录按角色展示不同数据，并经过双因素认证。
3. 总览同时提供 24 小时车辆运行热力图、实时充电曲线、累计 / 今日充电量、充电次数、碳减量、累计 / 今日里程、最新 5 条单车里程、车辆总数 / 在线数 / 充电数 / 故障数 / 安全评估分数、最新 5 条告警。在线按最近 60 秒判定。严重告警车辆在总览单独展示，直至故障解除。
4. 地图支持缩放、平移、全屏、测距和区域聚合。在线为绿、离线为灰、充电中为蓝、告警为红。点选展示在线状态、最近上报时间、总里程、今日里程、速度、SOC、输出电压、电流、功率、单体最高 / 最低电压与温度及温差。弹窗每 10 秒刷新，可进入单车详情。
5. 监控统计按第 3.3 节口径计算，每 30 秒刷新，数字可下钻到车辆列表。充电热力图支持今日 / 本周 / 本月 / 本季 / 本年与自定义起止日期，按使用率分五档着色。
6. 车辆列表、单车详情、历史回放、告警的字段、页签时刻联动、轨迹分色与第 3.3 节一致。单次回放最长 30 天。严重告警进入重点关注池。报文以十六进制与 ASCII 对照查看。实时故障可导出，导出记入审计日志。
7. 短信、微信小程序、站内信按第 3.3 节规则推送故障告警与满电提示。同一车辆同一告警 5 分钟内不重复发送短信。小程序可查看总览指标、本人车辆状态与告警，并可确认收到告警。
8. 基础数据四类档案、用户档案字段与第 3.4、3.5 节一致；采购人超级管理员可创建账户并分配权限。
9. 报告中心可出具周 / 月 / 半年 / 年运行监控报告，以及故障统计周报、接入情况周报、高危报警专项报告、车辆信息核查报告。
10. 实时数据持续入库，历史轨迹与统计回放可按车辆、时间查询。
11. 接入任务记录资料到达时间，超过 7 天未完成可识别；季度新车接入率可统计，目标 100%；不能协议对接的车辆可登记 OBD 等替代方式。
12. `npm run build` 通过。`node scripts/check-requirements.mjs` 对第 4 节矩阵全部通过。F-03-09、F-07、F-08、F-09-01、F-09-02 的 WARN 在对应功能纳入矩阵前可以存在。F-09-01 的 Web 能力已由 F-01～F-06 覆盖。
