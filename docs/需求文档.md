# 首都机场（飞行区）电动车辆安全运行监控管理平台 — 需求文档

> 开发基线：本章对齐《第三章 项目需求》本次给定条款（总述、运行服务、平台功能第 1–5 项及功能总述）。
> 带「*」的条款及其全部下级条款为重要技术条款，负偏离将导致应答被否决。本次给定正文未标出具体「*」条款；后续原文补标后，按原文执行。
> 功能编号 `F-xx` 用于页面开发与 `scripts/check-requirements.mjs` 对照。`OPS-xx` 为运维与服务承诺，不要求单独业务页面。

## 1. 项目概述

采购人采购首都机场电动汽车安全运营管理服务。供应商提供飞行区内电动车辆安全运行监控管理平台，把现存及新增电动车辆全部纳入监控。

| 项 | 要求 |
|----|------|
| 监控范围 | 首都机场飞行区现存及新增电动车辆，全部接入 |
| 当前规模 | 约 1900 余辆 |
| 2029 年规模 | 空侧约 2800 辆，其中通用车 1600 辆、特种车 1200 辆 |
| 硬件 | 平台运行及数据服务器由采购人提供 |
| 运维责任 | 应答人负责服务器及数据运维 |
| 容量设计 | 按 2800 辆、365×24 小时持续上报做接入、存储、查询与展示 |

## 3. 平台功能（原文「二」）

平台用大数据分析做碳减排与能源消耗等经济性、环境性指数，以及可靠性指数、安全性指数的分析与展示。数据监视同时提供 Web 与移动端。

车辆运行数据 24 小时实时监控，可查看最新数据与状态，并支持历史数据统计回放。

每周、月、半年、年出具新能源汽车运行监控报告，做定量分析，并给出生产运营建议。

## 5. 验收标准

1. F-01 至 F-06 的页面可访问、有数据、可交互。
2. 登录按角色展示不同数据，并经过双因素认证。
3. 总览同时提供 24 小时车辆运行热力图、实时充电曲线、累计 / 今日充电量、充电次数、碳减量、累计 / 今日里程、最新 5 条单车里程、车辆总数 / 在线数 / 充电数 / 故障数 / 安全评估分数、最新 5 条告警。
4. 地图点选展示在线状态、总里程、速度、SOC、输出电压、输出电流、输出功率、单体电压与温度。
5. 充电热力图支持日 / 周 / 月 / 季 / 年与自定义周期，颜色表示充电桩使用程度。
6. 车辆列表、单车详情、历史回放、告警查询的字段与第 3.3 节一致；实时故障可导出；可查看报文；严重告警标记为重点车辆告警。
7. 短信或微信小程序可推送故障告警与满电提示。
8. 基础数据四类档案、用户档案字段与第 3.4、3.5 节一致；采购人超级管理员可创建账户并分配权限。
9. 报告中心可出具周 / 月 / 半年 / 年运行监控报告，以及故障统计周报、接入情况周报、高危报警专项报告、车辆信息核查报告。
10. 实时数据持续入库，历史轨迹与统计回放可按车辆、时间查询。
11. 接入任务记录资料到达时间，超过 7 天未完成可识别；季度新车接入率可统计，目标 100%；不能协议对接的车辆可登记 OBD 等替代方式。
12. `npm run build` 通过。`node scripts/check-requirements.mjs` 对第 4 节矩阵全部通过。F-03-09、F-07、F-08、F-09-01、F-09-02 的 WARN 在对应功能纳入矩阵前可以存在。F-09-01 的 Web 能力已由 F-01～F-06 覆盖。
